links hidden; Enter opens it, Escape closes it and returns focus to the button, ArrowDown focuses the first service; the
finite element page's h1 and its "Open the studio" link pointing at `/studio`; the contact page's `mailto:` link; no link

one of them navigates. The overflow scenario now also covers `/services/finite-element-modeling` and `/contact` at 390 and
768 px.

The two failures are not this change's:

- `tests/browser/research.spec.ts:27` expects 4 `.method-entry` rows for the search "Tsai" in the ply failure topic and
  finds 5. The search reads each method's name, detail, equation and reference location (`components/physics-browser.tsx`
  L11-14); none of those changed on this branch (`git diff origin/main -- lib/physics-foundations.ts` is empty; the branch
  changes three `source` strings in `lib/physics.ts`, which the search does not read). The spec is not in CI. Not re-run on
  `main` here, so its state there is UNVERIFIED.
- `tests/browser/studio.spec.ts:209` ("a fresh form's choices start blank") fails on `main` since the studio opens on the
  chat; pull request #115 (`fix/ci-red-jobs`) adds the click on the "Full form" tab. It will pass once that merges and this
  branch takes it.
