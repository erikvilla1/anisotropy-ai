# ADR-0045: Abaqus results come from a script under `abaqus python` that writes CAE's field-report CSV, and Abaqus is an optional second reference solver

- Status: Proposed
- Date: 2026-10-24
- Decided by: Founder, 2026-10-24 ("do both chunks now", on the plan "Abaqus headless: extraction script and runner, both chunks now") and 2026-10-25 after the walkthrough (ran the two test files, 14 passed; ran the script by hand on the attempt-15 ODB and compared its CSV with the team's; read this record: "looks like everything looks good"; the S12 record stays as it is; the writer's default flips in a separate change; the worktree is folded into the main folder) | Drafted by: Claude Code
- Related: [ADR-0030](ADR-0030-models-from-a-spec-calculix-as-reference-solver.md) (CalculiX is the reference; its context is corrected here), [ADR-0029](ADR-0029-finite-elements-own-membrane-kernel-validated-against-abaqus.md), [ADR-0002](ADR-0002-si-units-inside-the-engine.md), [ADR-0003](ADR-0003-reject-invalid-input.md), [ADR-0039](ADR-0039-every-attempt-keeps-its-folder-and-its-row.md), `fea/tools/abaqus_extract_fields.py`, `fea/src/anisotropy_fea/abaqus.py`, `fea/tools/run_abaqus.py`, `fea/tests/test_abaqus_extract.py`, `fea/tests/test_abaqus.py`, [installing the tools](../installation-fea-tools.md)

## Context

Every coupon comparison against Abaqus has gone through the GUI: a job run in Abaqus/CAE, the ODB opened, Report > Field Output used once per quantity, the CSV files carried by hand. `anisotropy_fea.abaqus_report` reads those files and `tools/record_from_report.py` turns them into a record (ADR-0030 amendment 2). The team's exports of 2026-10-16 hold S11, S22 and Mises at the two outer faces, no S12, no reactions, no displacements, so several rubric rows carry our value where the team's is missing (ADR-0043). A hand export cannot be reproduced or hashed.

Facts checked on 2026-10-24 on the founder's machine:

- Abaqus 2025 is installed, `C:\SIMULIA\Commands` is on `PATH`, and `abaqus python` is Python 3.10.5. `abaqus information=environment` names the licence: `34000@its-flex-srv.ucsd.edu`, `academic=TEACHING`. ADR-0030 wrote this install off as "probably expired and in any case not for company work"; the first was wrong, the second holds.
- `abaqus licensing lmstat -a` lists the teaching features (`abaqus_teaching`, 960 seats; `abaqus_extended_teaching`, 120 seats, expiring 2027-07-31).
- An ODB opens only in its own Abaqus version or newer; the team's Abaqus/CAE 2026 files cannot be read here.
- The odbAccess module gives, per stress value, the element label, the integration point, the section point (number and description), the components by label and the Mises invariant; it gives no coordinates. The strings a real ODB holds (our X840PW-UNT-L1 deck solved by Abaqus/Standard 2025): the frame description `Increment      1: Step Time =    1.000` (padded, as in the team's CSV), section point descriptions `SNEG, (fraction = -1.0), Layer = 1` at a face of the section and `fraction = -0.900000, Layer = 1` inside, the section category `shell < composite > < elset = NAME >`. The default field output holds the two outer faces only: 1600 values for 800 elements. Python's `subprocess` runs `abaqus.bat` in list form.

## Options considered

1. **Keep the hand exports.** No code. Not reproducible, incomplete, and the one step of the loop no agent can run.
2. **Parse Abaqus's printed output** (`*El Print`, `*Node Print` into the `.dat`), as the CalculiX path does. Needs a second `.dat` parser (Abaqus's layout is not CalculiX's), gives no section-point faces in the shape the reports have, and the committed decks' print tables turned out to be refused by Abaqus/Standard (below).
3. **A CAE script** (`abaqus cae noGUI=`) calling CAE's own report writer. Byte-identical to a hand export, but it needs a CAE seat, starts CAE for every export, and keeps the GUI product in the loop.
4. **An odbAccess script under `abaqus python` that writes CAE's CSV layout** (chosen). No CAE seat: `abaqus python` reads an ODB with the odbAccess module. One code path for the team's exports and ours. Plain Python, so its parts are tested without Abaqus. Its strings are composed, so they had to be checked against a real export (evidence).

Also considered: Abaqus as the reference solver instead of CalculiX. Rejected: a teaching licence bound to one server, not usable for company work, unavailable on CI (ADR-0030 stands).

## Decision

- `fea/tools/abaqus_extract_fields.py` runs under `abaqus python` and writes, for one ODB, one CSV per quantity (S11, S22, S12, Mises) with the header and the Section Point text of a CAE field report, one section point per layer (`--layer-point bottom|middle|top` when the field holds several), rows sorted by element label then section point, nine-digit numbers, LF line endings; the reactions at every node that carries one as `<job>-RF.csv`; the provenance as `<job>-extract.json` with the solver, creation time, step, frame, instance, section points and each file's SHA-256. The values are the ODB's own numbers in the deck's units (ADR-0002). It refuses what it would otherwise guess (ADR-0003): several steps or instances without a name, more than one frame after frame 0 without `--frame`, an integration point other than 1, an element without section points, an unknown quantity. It imports nothing of ours and odbAccess only where it reads, so `tests/test_abaqus_extract.py` runs its parts under ordinary Python.
- `anisotropy_fea.abaqus` mirrors `calculix.py`: `find_abaqus` (argument, `ANISOTROPY_ABAQUS`, `abaqus` on PATH), `run_abaqus` (`abaqus job=<job> input=<job>.inp interactive ask_delete=OFF cpus=<n>` in the working folder; a stale `<job>.lck` is refused, not deleted; errors are read from the `.msg`, the `.dat` and the `.sta`, because Abaqus exits with code 0 after an input error), `extract_fields` (the script under `abaqus python`), `read_provenance`, `read_reactions`.
- `fea/tools/run_abaqus.py <spec> --out <attempt>/run/abaqus` writes the deck, solves it, exports the fields and writes the record against the kernel (`report_quantities` for the ply stresses, the reactions summed over every `RF-*` and `Grip-*` node set), then prints how many of the record's numbers the kernel reproduces. `abaqus` is a run kind of the attempt folder (ADR-0039); `tools/new_attempt.py` prints its `--out`.
- Abaqus is an optional second reference beside CalculiX, under the teaching licence: the course and the team comparison only, never a customer deliverable. Nothing in the pipeline needs it; the tests that use it skip without it.
- `write_abaqus(split_print_tables=True)` writes one variable per `*El Print` table, which Abaqus/Standard accepts; the run tool uses it. The default stays as it was, so the committed decks keep their text and the records their digests, until the default is flipped and the decks and records are regenerated together (consequences).

- The licence, the Python version and the release, read on 2026-10-24: `abaqus information=environment` (`abaquslm_license_file='34000@its-flex-srv.ucsd.edu'`, `academic=TEACHING`), `abaqus python -c "import sys; print(sys.version)"` (3.10.5), `abaqus information=release` ("Abaqus 2025"), `abaqus licensing lmstat -a` (the teaching features above).
- The strings and counts of a real ODB (`C:/temp/Job-2.odb`, our X840PW-UNT-L1 deck run from CAE on 2026-10-24): one instance `CFRP-COUPON-1`, 891 nodes, 800 S4R elements, one section category with 30 section points (ten layers, three each), the stress field at 1600 values (two outer faces), components `S11, S22, S33, S12`, reactions at assembly nodes 1 and 2 of ±105914.94 N. The script's first run on that ODB wrote four files of 1600 rows that `read_field_report` reads back with faces SNEG and SPOS at layers 1 and 10; its Section Point column has the team's shape (`shell < composite > < elset = ... > : SNEG, (fraction = -1.0), Layer = 1`). Its Section Name differs from the team's by a `-1` suffix Abaqus adds to our section elset (`ASSEMBLY_CFRP-COUPON-1_COMPOSITELAYUP-1-1-1`); the parser does not read that column.

S11 600 of 600, S22 600 of 600, Mises 600 of 600 within the rule. Reactions at `RF-Top` and `RF-Bottom` 105914.94 N against the kernel's 105993.25 N, +0.074 %. - Tests, 2026-10-24 in the worktree: the whole fea suite `uv run pytest` gave 358 passed, 21 skipped, 1 failed in 241 s, the Abaqus solve of the public IM7/8552 coupling deck among the passed (one seat, about 25 s). ## Consequences

- Easier: one command per side; exports that are the same bytes every run and carry their digests, for the attempt log and the audit form's Record sheet; the team can return S12, reactions and displacements with the same script on their 2026 install; an agent can run the whole loop.
- Harder, and what we now depend on: a licensed, version-bound tool, used within the teaching licence's terms only; tokens from a shared pool, so no blind refinement loops; CI never runs it; the script travels to whoever made the ODB.
- Found and left for a decision: the committed `-abaqus.inp` decks are not valid Abaqus/Standard input as written (the print tables) and their citation comment lines exceed Abaqus's 256-character line (a warning). Flipping the writer's default changes every committed deck's text, the digests in the five records that name a generated deck, and the deck digest the audit package's Record sheet carries (ADR-0044); it belongs in its own change after the audit branch lands.
- Not done here: displacements at the probe nodes and the section points inside the layers in the record; a reading beside the Abaqus record; the case page's result block, which reads `ours/verification/` and does not yet know a run-folder record.
- The next chunk, set by the founder on 2026-10-25: the team never exports by hand again, and their Abaqus files are read thoroughly. The constraint is the version lock: their Abaqus/CAE 2026 ODBs cannot be opened by the 2025 install here. In order of preference: (A) Abaqus 2026 on this machine under the same teaching licence, so the team sends `.odb` and `.inp` and everything is read here (first step, the founder's: ask the team's lab or UCSD IT for the install media); (B) until then, the team runs this script on their machine, one command, and sends the folder it writes; (C) in either case, the script grows to yield everything we compare from one ODB: displacements, strains, section forces, every section point of every layer, every frame, the history outputs.

## How we will know it was wrong

- CAE's Report > Field Output and the script disagree on a value or a string for the same ODB. The check to run on the team's machine with their ODB, which this install cannot open.
- A later Abaqus release spells the section point or frame text differently, so the parser's regex stops matching: the first run on that release shows it.
- The licence server stops serving this machine, or its terms are read as excluding this use: Abaqus drops out of the loop and CalculiX stays, with nothing else to change.
- The S12 disagreements spread beyond the band's edge rows on a finer mesh or another coupon: then the element-formulation reading above is wrong.

## Amendment 1, 2026-10-25 (the rule for S12: judged where it carries load; a stated floor on the 0 degree faces until then)

**Context.** The record of attempt 15 (evidence above) compared S12 on the two outer 0 degree plies, where it is a residual of the grip constraint: at most 15.4 MPa against about 15800 MPa axial. Under the record rule, 1 % of each value with a floor of 2 % of the group's largest magnitude (an allowance of about 3.2 MPa), 64 of 600 S12 values at 32 elements in the band's edge rows were outside, by at most 5.6 MPa, while S11, S22 and Mises agreed 600 of 600 on the same elements: the difference is the formulation noise between S4R and the bilinear membrane element, not a model error. The rubric's stress row (`docs/audit/rubric.toml` 0.3, "Ply stresses S11, S22, S12 in material axes") judges each quantity against its largest team value in the band, which for S12 on the 0 degree faces would allow 0.15 MPa, and it already asks for field reports at every section point.

**Options.**
1. Keep S12 judged like S11 and S22 with the 2 % floor. Rejected: on the 0 degree faces S12 is noise-level, so the rule fails on formulation noise and says nothing about the model.
2. Judge S12 in a narrower band, y 30 to 50 mm. Not taken as the rule: it hides where the noise sits without saying why; it may serve as a reading.
3. Judge S12 where it carries load, the +-45 plies, where 1 % is a real test; that needs the interior section points in the export. Until then, a stated floor of 4 % of the group scale on the 0 degree faces, so differences below 0.04 % of the axial stress do not count, the measured noise being 0.035 %.

**Decision.** Option 3, accepted by the founder on 2026-10-25 ("i accept the rule for S12", on this recommendation). The attempt-15 record was re-read with floor 0.04: 2404 of 2404 within the rule; its notes say so and why. The rubric row keeps its text for now; at the rubric's next version the row states this rule, which raises the rubric version (ADR-0043). The export of every section point is part of the next chunk (consequences, path C).

**Evidence.** The attempt-15 record in `.local/fea/X840PW-UNT-L1/ours/runs/attempt-15_2026-10-24/run/abaqus/` and its row on the case page. The breakdown of 2026-10-24: all 64 outside values are S12, largest |S12| 15.36 MPa, largest difference 5.64 MPa, at 32 elements in the rows nearest y 25 and y 55 mm; with floor 0.04, `compare_record` gives 2404 compared and 0 outside (2026-10-25). S12 in a +-45 ply is a hand estimate only, G12 times the ply shear strain, about 6480 MPa times 0.13 for the 10 mm pull over 80 mm, roughly 850 MPa; no solver value yet.

## Amendment 2, 2026-10-25 (every generated deck runs in Abaqus/Standard as written)

**Context.** The consequences above left two faults in the generated decks for a separate change: the combined `*El Print` tables, which Abaqus/Standard refuses, and comment lines longer than Abaqus reads. Abaqus/CAE hid both, because File > Import drops `*El Print` and `*Node Print` (its import log of 2026-10-25 lists them as "not yet supported") and writes its own deck. The founder asked for the change on 2026-10-25 ("ok do 1 and 2", on the recommendation "make our decks run directly in Abaqus"). The first direct run after splitting the tables still warned `Line #7 has been truncated`: that line was 253 characters but 258 bytes, holding five "·" of two bytes each in UTF-8, so Abaqus's limit of 256 is in bytes. The same run recorded no reaction for the nodal grips: the ODB spells the deck's instance `Coupon-1` as `COUPON-1`, and `reactions_by_set` compared names with case.

**Options.**
1. Flip the writer's default and keep `split_print_tables=False` available. Rejected: it writes input Abaqus refuses, and nothing reads the combined form.
2. Write one variable per table always and drop the option (chosen).
3. For the lines: wrap comments at a character width with a margin (200, say). Rejected: not a rule; enough two-byte characters still pass the limit.
4. Replace the non-ASCII characters in deck comments by ASCII. Rejected: the citation would no longer read as the library holds it.
5. Wrap comment lines at spaces by their UTF-8 bytes, and refuse a single word that cannot fit a line rather than cut it (chosen; a cut URL would break).

**Decision.** Options 2 and 5, drafted by Claude Code and confirmed by the founder on 2026-10-25 ("do 1-3", on the walkthrough of the two choices). `write_abaqus` writes `SF`, `SE`, `S` and `E` in tables of one variable each, and wraps a heading comment longer than 256 bytes (`MAX_LINE`, `line_bytes`), indenting the continuation two spaces more. `tools/run_abaqus.py` writes the spec's deck unchanged, so its run deck and the deck in `decks/` are the same file. `reactions_by_set` moves to `anisotropy_fea.abaqus` and matches the instance without regard to case (Abaqus names are not case-sensitive). The committed Abaqus decks are regenerated, and the two committed records that name one take the new digest after a check that the old deck was the one each record was made from and that old and new decks are the same model (`deck_equivalence`).

**Evidence.** [Evaluation of 2026-10-25](../evaluations/fea/2026-10-25-abaqus-decks-as-written.md): the committed public open-hole deck run directly in Abaqus/Standard 2025, the same digest as the committed file, the one warning the missing F12, no truncation, reactions recorded at both grips and all 12 of the record's numbers within 3 % of the kernel; the test that solves the committed coupling deck as written; the suite at 788 passed, 7 skipped.
