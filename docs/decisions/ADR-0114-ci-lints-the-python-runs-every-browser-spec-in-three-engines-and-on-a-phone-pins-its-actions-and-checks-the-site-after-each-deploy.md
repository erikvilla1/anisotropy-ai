# ADR-0114: CI lints the Python, runs every browser spec in three engines and on a phone, pins its actions, and checks the site after each deploy

- Status: Proposed
- Date: 2026-11-18
- Decided by: Founder, 2026-11-17 ("no i think we should leave our CI, what i want is more about what does th CI do, where we can improve on that as well", then "all look very importannt lets build them", on seven improvements listed for him); Founder, 2026-11-18 ("Weekly, all coupons", on how often to check his real coupons on his PC) | Drafted by: Claude Code
- Related: [ADR-0056](ADR-0056-the-hosted-tier-runs-on-cloudflare-with-one-solver-image-r2-access-and-neon-postgres-invite-only.md) (the hosted tier; amendment 10, the API restarted by a deploy); [ADR-0051](ADR-0051-the-coupon-studio-a-browser-page-through-the-api-with-the-fea-package-computing-every-number.md) (the studio's browser tests); [ADR-0042](ADR-0042-course-keys-and-team-models-stay-off-the-repository.md) (what stays local); `.github/workflows/tests.yml`, `.github/workflows/deploy.yml`, `.github/dependabot.yml`, `ruff.toml`, `playwright.config.ts`, `playwright.site.config.ts`, `tests/browser/phone.spec.ts`, `scripts/check-hosted.py`, `api/src/anisotropy_api/main.py` (`GET /version`), `fea/tools/weekly_coupons.py`, `scripts/weekly-coupons.ps1`
- Area: process, hosting, website, api

## Context

- On 2026-11-17 the Tests workflow ran nine jobs, about 11 minutes a push. The repository is public, so the minutes cost nothing; the founder chose to keep every job and asked what CI misses.
- Six of the 18 browser spec files ran in CI (calculator, studio, workspace, abaqus-card, import; studio-live only by hand). The other twelve (home, demo, intro, team, research, provenance, shell, expansion, portfolio, material-analysis, physics-foundations, textbook-materials) ran only when someone ran them.
- Every browser test ran in Chromium. Safari on a Mac and every browser on an iPhone or iPad use WebKit; nothing tested it, or Firefox, or a phone as a phone (touch, pixel density, a phone's user agent): the phone specs set a narrow window only.
- No Python lint ran. ruff's own default rules found 986 findings, most of them style; Pyflakes and flake8-bugbear found 297, among them unused imports, variables never read and loop variables never used.
- The deploy's actions were named by a moving tag (`@v7`, `@v4`) while they hold the Cloudflare token and the database address. No tool proposed updates.
- On 2026-11-17 a deploy reached the hosted API only after 20 idle minutes and nothing reported it (ADR-0056 amendment 10). Nothing checked the site after a deploy.
- A pull request uploads a preview version of the Worker that is never visited: `wrangler.jsonc` has `preview_urls: false`, and Cloudflare gives no preview address to a Worker that implements a Durable Object, which the containers are ([Cloudflare's version URLs page](https://developers.cloudflare.com/workers/configuration/previews/)).
- The founder's real coupons live under `.local/` on his machine and never reach the public CI (ADR-0042).

## Options considered

1. Lint with ruff's default rules: 986 findings, mostly style, and the defaults change between releases. Rejected for a named set.
2. Lint with a named set, Pyflakes, pycodestyle's E4/E7/E9 and flake8-bugbear, leaving out the rules that are style or a change of behaviour: chosen.
3. Run the twelve specs by adding each to an existing configuration: a new spec would again be missed. Rejected for one configuration that takes every spec no other claims.
4. Run every spec in every engine as Playwright projects in one job: one long job. Rejected for a job per engine run side by side.
5. Test a phone by running every spec at a phone's size: most specs test the desktop layout and would fail for no fault. Rejected for one phone spec over every page, as an iPhone in WebKit and an Android phone in Chromium.
6. Pin actions by tag and trust the tag: rejected; a tag can be moved. Pinned to the commit, with the version in a comment Dependabot updates.
7. Dependabot per dependency, weekly: a stream of pull requests. Rejected for one grouped pull request a month per kind (actions, npm, Python), majors apart.
8. After a deploy, poll `/api/healthz`: it answers from an old container too. Rejected for `GET /version`, which names the commit the API runs, waited on until it is the deployed one, then one public coupon job through the queue.
9. Test the preview by giving it an address: needs Cloudflare's newer Previews, a container per preview and Access on its address, a hosting change for the founder to decide. Rejected for now.
10. Run the pull request's Worker in CI as it runs on Cloudflare: `wrangler dev` starts the Worker and both containers from the Dockerfile in Docker, with the local queue, a PostgreSQL service and moto for R2, and the deploy's check runs against it. It proves the bundle, the image and the queue work together without any Cloudflare change: chosen.
11. The real coupons every night, every coupon: about an hour of the founder's PC a night for a code that changes a few times a week. Weekly, all coupons: chosen by the founder. Only the public coupons in CI: they already run there. Not at all: a change that moves a team number goes unseen until a package is rebuilt.
12. Re-solve each coupon in place: `run_coupon.py` prunes the coupon's earlier attempts and rewrites its case page. Rejected for a copy of each coupon, run there.

## Decision

- `ruff.toml` names the rules (F, E4, E7, E9, B; E402, E731, E741 and B905 left out, each with its reason) and the Tests workflow runs `uvx ruff@0.17.5 check .`.
- `playwright.site.config.ts` runs every spec in `tests/browser/` that the calculator, studio and live configurations do not; the `site-browser` job runs it in Chromium.
- `BROWSER=firefox` or `BROWSER=webkit` picks the engine (`playwright.config.ts`); the `other-browsers` job runs the site's and the workspace's specs in each, on a virtual display (`xvfb-run`). Firefox runs with its window, since without one it gives no WebGL and the 3D views say so instead of drawing. The specs turn the wheel through `tests/browser/wheel.ts`: in Firefox a turn goes a little under a window at a time, since Firefox scrolls at most about a page for one wheel event; in WebKit each wheel event comes to rest before the next, since a second one during WebKit's glide retargets it. Where an engine, or Playwright's driving of it, differs, the spec checks what that engine allows and says why: the finger drag through Chromium's DevTools protocol is skipped in the other two; in WebKit, Playwright's route handlers get no body for a file upload, a fetch the page aborts comes as a page error "due to access control checks" (`tests/browser/page-errors.ts` leaves those out), and a file a route handler answers fires no download, so the address the page asked for is checked instead; in Firefox, a button focused by a script after a click has no focus ring (`:focus-visible`'s rule as written), and the header's bar does not stay for it. A line is typed into the chat only once React has hydrated the box (`tests/browser/hydrated.ts`): one typed sooner is lost.
- The calculator's library list clips option names longer than its field (`app/calculator/calculator.css`). WebKit counted them in the page's width, and on an iPhone the page scrolled sideways by about 40 px.
- `tests/browser/phone.spec.ts` opens every page of the app (from `app/**/page.tsx`, the redirects left out) as a phone and checks no sideways scroll and no script error, then taps through the menu to the workspace and answers the chat's first question with a tap.
- Every action in the three workflows is pinned to a commit; the workflows' token is read-only unless a job says otherwise; `.github/dependabot.yml` groups updates monthly.
- The `worker-run` job runs the pull request's Worker, the site and the image under `wrangler dev` (PostgreSQL as a service, moto as R2, the local queue), then `scripts/check-hosted.py` and the studio's live browser run against it.
- The browser specs of the site run one at a time (`workers: 1`): the intro, shell and demo specs count a fade's frames, and a second browser on a runner's four cores drops them.
- The Deploy workflow's `check` job runs `scripts/check-hosted.py` after each production deploy: the home page, `GET /api/version` until it names the deployed commit (10 minutes at most), and one public coupon job (the IM7/8552 fixture, actor `test`, no PDF) to its result. Access admits it with a service token in the repository secrets `CF_ACCESS_CLIENT_ID` and `CF_ACCESS_CLIENT_SECRET`; without them the job warns and passes.
- The founder's real coupons are checked weekly on his PC (`scripts/weekly-coupons.ps1 -Register`: Sundays at 2 AM, or as soon after as the PC is on). The script keeps a worktree of `origin/main` outside his checkout and runs `fea/tools/weekly_coupons.py`, which copies each coupon under `.local/fea/` (its solver outputs left behind), re-solves the copy with `run_coupon.py --every-test --no-pdf`, and sets every compared value, ours and CalculiX's, and the run's answer beside last week's, kept in `.local/weekly/snapshots/`. The report and the snapshots stay under `.local/weekly/` (ADR-0042); a Windows notification says when a number moved or the check failed, and a week where nothing moved is quiet.

## Why (evidence)

- Lint: `ruff check --isolated --select E4,E7,E9,F,B .` found 297 findings on main (ad0ce15); with the four rules left out, 68, all fixed or marked where the closure is used within its own pass of the loop; `uvx ruff@0.17.5 check .` passes. After the fixes: engine 525 passed; mcp-server 39 passed; api 546 passed, 138 skipped (no database here); fea 1697 passed, 13 skipped (Abaqus, Tectonic and the local coupons absent).
- The twelve specs, Chromium, on the built site: 81 passed, 7 skipped (switches the specs name), 1 failed, the demo's "a beat takes its own time" at 5.1 s against a 4.8 s limit while ruff and an install ran beside it; run again alone with two workers, `demo` and `portfolio` 17 of 17 passed. The two portfolio cases said to fail on main passed.
- The phone spec, Chromium: 2 passed, 18 pages.
- Firefox and WebKit: the browsers cannot be downloaded in the cloud session that wrote this (the network policy refuses their hosts), so the evidence is the pull request's runs. The first (5386be0), Firefox: site specs 75 passed, 9 failed, 7 skipped; workspace specs 46 passed, 7 failed. WebKit: its system packages had not finished installing after 20 minutes on that run; the job now stops at 40.
- The second run (d55a280, with main's model tree merged in): Firefox, site 78 passed, 5 failed, workspace 46 passed, 10 failed; the WebGL settings and Mesa tried after the first run had not helped (12 of the 15). In Firefox with its window, the team spec found a card lifted under the virtual screen's own pointer, and now moves the pointer off the cards first; the header spec's focus ring case is as in the Decision. - Site specs, two workers at once on CI's four cores: `intro.spec.ts:352` saw 4 frames of a fade for its 5; on this session's four cores `shell.spec.ts:395` failed the same way. With one worker here: 84 passed, 7 skipped, in 5.3 minutes; after the wheel helper, the shell, demo, intro and phone specs 48 passed, 1 skipped, in Chromium.

The studio's live spec then waited ten minutes for "Load example": it had not been run since the tension screen (ADR-0090) took the form's place for a visitor, so it now goes through the screen a visitor sees, or the form when every test is offered.

With a token: UNVERIFIED until the secrets are set.
- `fea/tools/weekly_coupons.py` on a scratch coupon built from the public IM7/8552 fixture: the first check set beside its record, nothing moved, exit 0, the coupon's own folder unchanged; a snapshot with one value changed by hand gave "moved" with that row listed and exit 1. - Action commits read with `git ls-remote` on 2026-11-18; each tag the workflows used points at the pinned commit, so nothing they run changes.

## Consequences

- A push runs four more jobs (lint, site-browser, Firefox, WebKit) beside the nine, in parallel; the minutes are free while the repository is public, about four times the browser minutes if it goes private (see the CI cost noted for the founder on 2026-11-17).
- A WebKit or Firefox failure may be the browser's own behaviour under test, not a product fault; such a case is fixed or skipped in that engine with the reason in the spec.
- The check after a deploy writes one coupon job a deploy into the hosted store under no signed-in person, and counts against that owner's daily cap; a refusal by the cap warns, not fails.
- The preview stays an upload with no address; `worker-run` shows that the pull request's Worker and image run together, not that they run on Cloudflare. Giving the preview an address is the founder's choice.
- The weekly check needs the founder's PC on once a week, with `uv` and `git` as his checkout already uses them; it re-solves every coupon in a copy, so the coupons themselves never change. Its first week is set beside each coupon's last record, which shows what today's decks change; each later week shows what the code changed.

## How we will know it was wrong

- A lint finding that is right code more than once a month: the rule leaves the set.
- The Firefox or WebKit job fails for the browser's own reasons more often than for the product's: run them on main only.
- A deploy whose API answers an old commit and the `check` job passes: the version check is wrong.
- The weekly check says a coupon moved when no code changed: the comparison's 1e-9 or the snapshot is wrong.
- Dependabot pull requests left unmerged for two months: the schedule or the grouping is wrong.
