## Context

- "Download model" over a model in the FEA workspace saves it as a file for a solver (ADR-0129). Nothing saved its shape for a CAD program. A wing has a STEP file of surfaces (ADR-0116) and a patch repair one of solids (ADR-0131), each from its own page; a coupon and a plate had none.
- A coupon's or a plate's mesh is cut from one description, the spec's `geometry` (`femodel.mesh_for_spec`): the length, the width, a dog-bone's outline (`dogbone.Outline`) and one hole at the middle. Its thickness is the sum of the section's plies. Bonded tabs are stated only when the spec carries a `[tabs]` table (thickness, bevel, material); the finite element model then holds the gripped length and carries no tab material.
- A STEP file as Gmsh's OpenCASCADE writes it (AP214, `AUTOMOTIVE_DESIGN`) holds shape, names and units. It holds no ply, no angle and no material.
- Gmsh is GPL and an optional extra of the fea package (`mesh`). It runs on the server only.
- A flat laminate differs from the wing and the repair in one way that matters here: every ply has the same outline, and the laminate has a thickness a designer needs (a fixture, a drawing, a mass).

## Options considered

1. Mid-surfaces and a part table, as the wing (ADR-0116). The file is the shell model's own geometry. A coupon then opens as a rectangle with no thickness: nothing to measure, weigh or fit in a fixture until the reader thickens it, and tabs become three stacked surfaces. The wing has a reason a coupon lacks: its skins are sized by the analysis and thickened in CAD afterwards.
2. One solid per part at its real thickness, and a part table. The laminate opens as the part a designer expects, with the thickness the plies sum to; tabs are separate named solids. The layup is not in the shape, so it has to be stated beside it, and the solid's thickness is the nominal sum of the plies, not a measured cured thickness.
3. One solid per ply, as the repair (ADR-0131). In the repair each ply has its own extent, so a solid per ply shows something. In a flat laminate it is n identical slabs: 8 bodies for the example coupon and one per ply for any other, with coincident faces between them, a file that grows with the ply count, and still no fibre direction in the file, only an angle in a name. It also reads as if the plies were modelled in CAD.

Where the file is asked for: a route of its own, as the wing and the repair have, or the existing download route with one more value. A route of its own would restate the access rules, the naming and the blocked-setup answer of ADR-0129.

## Decision

Option 2, through the existing download.

- The laminate is one solid: the outline the mesh is cut from, extruded by the sum of the model's ply thicknesses, in millimetres, x across the width and y along the length from the same corner as the mesh, z = 0 at mid-thickness. A hole is drilled at `mesher.hole_centre`, which the mesher now reads too. Nothing is typed twice. The shape is drawn from the checked spec and cuts no mesh, so the element size is no part of the file and a fine model costs what a coarse one does.
- Bonded tabs are four more solids, drawn only when the coupon states their thickness: on the gripped length at each end, on each face, with the bevel the coupon states toward the gauge section. A coupon that gives a gripped length and no tab thickness gets no tab. Tabs that would reach a dog-bone's fillet, or a bevel longer than the tab, are refused with the reason: their outline is not stated.
- A size under 0.001 mm is refused before the kernel is asked, with the size named, in the coupon's own units as every refusal of a shape is: the laminate's length, width or thickness, a hole's diameter, the material beside a hole, a tab's thickness or length, and the outer face a bevel leaves. The kernel merges points 1e-7 mm apart; the limit is four orders above that and far below any size a coupon is cut to. Whatever else the kernel cannot build is answered as a refusal in plain words that carries none of the kernel's.
- Every solid is named ("Laminate", or "Coupon" for one isotropic material; "Bottom tab, top face" and so on). A file of several solids is an assembly named after the coupon.
- Where the layup is: in the part table that comes with the file in the header `X-Anisotropy-Model-Parts` (each part's layup as the coupon writes it, ply count, ply thickness, part thickness, material, volume, and whether the finite element model carries it as material), in the file's own header (`FILE_DESCRIPTION`, which also states the axes, that angles are counted from y and that plies are listed from the face at -z up), and on the page, which prints one line per part after the save. The file and the page both say that a STEP file holds no plies; for a model of one material the page names the material instead of a layup.
- The part table stays in a header, with a hard cap of 4096 bytes. An ordinary table is under 1000 bytes; a larger one is left out whole, and the page then says that the file's first lines state what each part is made of. The two other ways lost. A JSON answer carrying the file would give this program another answer than the two solver files of the same route and put a file of tens of kilobytes inside a string. A second request for the table would draw the shape twice or keep it between requests, and the route keeps nothing. The table is a convenience of the page: the file's own header states the same.
- What a row may hold is bounded where the rows are judged (`intake`), for every file of the route: a coupon's name is at most 80 characters, as the API's `coupon` field and a deck's names are, a tab's material is at most 80, and a size that is not a finite number is stopped at its row.
- Text written into the file (the header's description, the products' names) is an ISO 10303-21 string: an apostrophe and a backslash doubled, any character outside printable ASCII by its `\X\`, `\X2\` or `\X4\` directive, so a name reads back as itself. The description is cut into strings of at most 64 written characters, so its lines stay under 80; the file's other lines are the writer's own. The helper is the wing's and the repair's too, and a name of plain ASCII is written there as before.
- It is offered as "CAD (STEP)" in the "Download model" menu, after the solver files, to everyone who is offered the model. `POST /v1/coupon-jobs/model?program=step` answers it under the rules of ADR-0129: the tests this request is offered (ADR-0089), a blocked setup as a 422 with its first reason, the file named `<designation>.step`. The check for a shape judges the rows, the names, the spec, the material and the plies as the other files' check does. What only a mesh decides (constraints, load, mesh, probes) is left pending and does not stop a shape. A 503 of the route says what happened and never the tool's own words, which may name a folder of the machine; the cause is logged.
- Where Gmsh is not installed the tool writes no file and says so, and the API answers 503 "The shape builder is not installed here", the words of the wing's and the repair's shape routes.
- The wing keeps its surfaces and the repair its solids per ply. This record does not change them.

## Why (evidence)

- One description: `cd fea && uv run --extra mesh pytest -q tests/test_coupon_shape.py` gives `128 passed`. For each of 12 cases over all 7 kinds the file is read back by OpenCASCADE and held against the model and the mesh: the laminate's box is the model's length, width and thickness to 1e-6 mm; every corner node on the mesh's edge lies on the file's outline within 1e-6 mm, on a first-order and on a second-order mesh; a hole's centre and diameter are the mesh's hole nodes' within 1e-6 mm; the volume is the outline's area times the thickness (relative 1e-9 for a rectangle, 1e-7 with fillets); the part table's thickness is the engine's plies' sum and the solid's z extent.
- A midside node of a second-order mesh is the middle of the straight line between its two corner nodes, so on a straight edge it is on the outline and on a curve it is inside it by the chord's sagitta. Measured: 0.0144 mm at the open-hole coupon's hole (3 mm radius), 0.0018 mm at a dog-bone's 76 mm fillet, 0 on a strip. `test_on_a_second_order_mesh_the_corner_nodes_lie_on_the_outline_and_a_midside_node_on_a_curve_lies_on_its_chord` holds each midside node on its chord to 1e-9 mm and its gap to the sagitta.
- A tab's bevel is on its end toward the gauge section at the stated angle (7, 15 and 45 degrees, within 1e-4 degrees of the faces read back), and the check fails for a tab bevelled at the coupon's end or overhanging the gauge section, two shapes of the same box and volume.
- The neighbours are unchanged: the same command over `tests/test_studio_tool.py tests/test_gmsh_mesher.py tests/test_open_hole.py tests/test_mesher.py tests/test_wing_shape.py tests/test_repair_shape.py tests/test_theory_markers.py tests/test_plate_kind.py` and `tests/test_values_input.py` with the new file gives `298 passed`; the whole fea suite gives `1612 passed, 14 skipped`.
- The route: `cd api && uv run pytest tests/test_coupon_step_api.py -q` gives `86 passed` (each kind, a test not offered, the plate, the name, the part table, a signed-in person's own folder, a blocked setup, a refused shape, no Gmsh, a tool that stops, the header's limit over a real HTTP server and with Node's fetch; a fresh tool and a warm worker). Twenty-two of them run the real tool behind the route and are skipped where the fea environment has no Gmsh, as it has none in the API's job in CI: there they have not run.
- The page's logic: `npx tsx --test tests/model-shape.test.ts` gives 6 of 6 passing, and no line it prints holds a banned term (`bannedIn`).
- In a browser, with the API played: the scenario "the model's shape downloads as a STEP file from the menu" in `tests/browser/studio.spec.ts` passes in Chromium against the built site (the entry after the solver files, the file's name, the saved line, the note, the part lines, a refusal in the service's words, no banned term), and so does "at phone width a long layup wraps inside the card once a STEP file is saved" (390 px, a layup of 114 characters and a material of 80 in one word each, no box round the note wider than it shows, the focus back on the button after each of the three files is picked with the keyboard).
- End to end on a local API with the real tool: the example coupon's file came back in 1.2 s, 15,948 bytes, named after the coupon (a fresh tool takes 1.0 s at an element size of 2 mm and of 0.002 mm alike), and the page saved it from the menu and printed "Laminate: [45/0/-45/90]s, 8 plies of 0.1829 mm, 1.463 mm thick, IM7-8552."
- Size: a file of one solid is about 16 kB (20 kB with a hole, 48 to 63 kB for a dog-bone, 85 kB with four tabs). A solid per ply would multiply the first figure by the ply count.
- The schema and the unit are read from the files: `AUTOMOTIVE_DESIGN` (AP214) and `SI_UNIT(.MILLI.,.METRE.)`.
- UNVERIFIED: no file has been opened in SolidWorks, Onshape, Fusion or any other CAD program. They have been read back by OpenCASCADE alone, the kernel that wrote them.
- No evidence yet on which form a customer's CAD work needs; the choice of a solid over surfaces rests on the reasoning under Options.

## Consequences

- A model set up in the workspace can be handed to a designer as a part with its real thickness, and the part table tells them the layup the shape cannot.
- The thickness in the file is the nominal one. A reader who needs a cured thickness changes the ply thickness in the model, not the file.
- A flat part's STEP file now differs in form from the wing's (surfaces) and matches the repair's (solids). The reason is stated above and in each file's header.
- The shape depends on Gmsh being installed with the fea package. The solver image has it; a laptop without the extra gets the 503.
- The file is not the same byte for byte from one request to the next: the writer stamps the time in its header. The run record keeps each file's digest.
- The header and the product names are rewritten in the written file by text, as for the wing. A change in the writer's text is caught by the tests that read the names back, and the tool refuses a file it cannot name rather than half name it.

## How we will know it was wrong

- A CAD program a customer uses does not open the file as named solids in millimetres, or reads another size than the model's.
- A customer asks for the plies as bodies, or for the mid-surface, more than once: then a second form is offered beside this one.
- A designer builds from the file with the wrong layup because the part table was not seen: then the layup has to travel in the file in a form their program shows.
- A coupon's STEP outline and its mesh's corner nodes are found to differ by more than the 1e-6 mm the tests hold.
- A setup that only its mesh stops gets a STEP file and the person takes the file for a checked model: then the shape waits for the whole check after all, with a limit on the mesh it cuts.
- A part table over the header's limit turns out to be ordinary (many parts, long names): then it moves out of the header.
