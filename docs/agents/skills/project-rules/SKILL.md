# Project rules

## When to use

Before any change in this repository, and whenever you must decide where content belongs.

## Procedure

1. Read `AGENTS.md` at the repository root and follow it. It is the authority. If this skill and `AGENTS.md` disagree, `AGENTS.md` wins; report the disagreement.
2. Read `docs/documentation-guide.md` before writing a decision record, a report or a changelog entry.
3. Decide where the content goes with the table below. If nothing in the table fits, stop and ask the founder.
4. Work on a branch and open a pull request. Never commit to `main`.

## Where content goes

| Content | Where | Rule |
| --- | --- | --- |
| Any number in an analysis result | Computed by the engine, `engine/src/anisotropy_engine/` | ADR-0001 |
| Any number in a finite element result | Computed by `fea/src/anisotropy_fea/` on the engine's laminate stiffness; an Abaqus deck is an input, never a source of results | ADR-0001, ADR-0029 |
| An equation the finite element kernel uses | `fea/docs/theory.md` with a `<!-- code: name -->` marker per function (paired by `fea/tests/test_theory_markers.py`); the manual build will read it in a later chunk | ADR-0029 |
| A finite element validation case | `fea/checks/cases/*.toml`: a deck, expected numbers, a source and a tolerance | ADR-0007, ADR-0029 |
| A finite element model for comparison | Generated from a spec by `anisotropy_fea.spec` and the writers, never a hand-edited deck, in its test folder (spec, `decks/`, `records/`, README). Our models of the team's coupons live in `.local/fea/<coupon>/` and are never committed; build them the way the team builds: their material, layup, grips and names, and their mesh seeding when they have built it. A public model of our own design, with a library material that may be cited, goes to `fea/checks/<test>/`. The team's own decks stay inputs in `.local/fea/<coupon>/from-team/<date>/` | ADR-0018, ADR-0030, ADR-0035, ADR-0042 |
| The argument for one model comparison (model, theory, code, reference solver, every number and its error) | Generated by `docs/models/build.py` from the record; the human reading is `<record>.md` beside the record and quotes numbers from the record or an evaluation note. Documents of local records stay in `report/` beside the record | ADR-0031, ADR-0032 |
| A team Abaqus deck or result export | `.local/fea/<coupon>/from-team/<date>/` only: it is the team's to publish. The comparison handed back to them and the zips stay under `.local/` too, in the coupon's `documents/` | ADR-0029, ADR-0035, ADR-0040 |
| An equation the engine uses | `engine/docs/theory.md`, plus a card in the website physics library (`lib/physics*.ts`) | ADR-0019 |
| A validation case | `engine/validation/cases/*.toml`: inputs, expected numbers and a source reference only, from a public source or constructed. A constructed case adds its closed form to `engine/validation/closed_forms.py` (no engine code), checked by `engine/tests/test_constructed_references.py` | ADR-0007, ADR-0042 |
| A material value from a public-domain or open-publisher source (MIL-HDBK-17F, NASA, NCAMP, datasheets) | The website material library in `lib/`, with a rights class and evidence; then `npm run export:library` so the engine sees it | ADR-0018, ADR-0020 |
| A value from a licensed reference (Daniel and Ishai, CMH-17, the course appendix) | Individual values with table and page only. Never scans, text, tables or PDFs | ADR-0010, ADR-0018 |
| User-supplied or customer data | Nothing public; private workspace only | ADR-0018 |
| Course problem statements or solutions, textbook pages, PDFs, unapproved lab data, secrets | `.local/` only. Never committed, never under `public/` | AGENTS.md |
| A course answer-key case or a homework reading; a coupon model built to the team's test design, or a number compared with the team's results | `.local/` only, never committed. Homework cases go to `.local/homework/<set>/ours/`, coupon models to `.local/fea/<coupon>/`. What is still committed leaves in chunks C4 and C5, the last a history rewrite; until then add none. The X840-Z60 material record stays | ADR-0042 |
| A choice between alternatives (library, algorithm, format, architecture, units) | A decision record in `docs/decisions/` from `_template.md` | AGENTS.md |
| Every change | One line in `CHANGELOG.md` under Unreleased | AGENTS.md |
| A new or changed agent skill | `docs/agents/skills/<name>/SKILL.md`, through a pull request | ADR-0023 |

## Pitfalls

- A source's rights class decides what may be shown. When it is unknown, treat the source as a licensed reference until the founder decides.
- Never invent evidence. Write "no evidence yet".
- Never claim a test passed without its output. Mark anything unchecked UNVERIFIED.
- The engine uses SI units inside; convert only where values enter and leave (ADR-0002). Invalid input is rejected, never defaulted (ADR-0003).

## Verification

- `git status` shows no file under `.local/` (which since 2026-10-21 also holds the former `References/` and `output/`, ADR-0037) and no `*.pdf`.
- The tests that cover the change pass, with their output shown: `cd engine && uv run pytest`, `npm test`, `npm run typecheck`.
